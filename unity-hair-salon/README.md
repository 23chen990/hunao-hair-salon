# 《胡闹理发店》Prototype 0.7 · 完整营业日闭环 V1

Unity `6000.5.8f1` / C# / uGUI，16:9 横屏。本版本仍使用程序化 Low-Poly 灰盒资源，优先验证位置、状态、交互、响应与完整游戏逻辑。

当前整合版本保留第六阶段五种正式订单和完整洗剪吹并发服务链，并采用 `PRE_OPEN → BUSINESS → CLOSING_GRACE → RESULT → CLOSED_MANAGEMENT → NEXT DAY PRE_OPEN` 经营闭环。营业时长、收尾时长、四段压力曲线、Rush、过载减压、并发上限和订单权重均集中在 `DayConfig`；口碑、自动吹风支架购买状态与金币余额跨 Day 保留。

## 最简单的试玩方式

直接打开 `Builds/HairSalonDemo.app`。如果 macOS 首次阻止打开，请右键应用并选择“打开”。

也可以使用 Unity `6000.5.8f1` 打开本目录，打开 `Assets/Scenes/HairSalonDemo.unity`，然后点击顶部播放按钮。

### 结构化剪发工位 POC

中央两张剪发工位现在由 `Assets/Resources/CutStations/cut-stations.json` 的同一个
`cut-station-classic-poc` 资产定义创建，分别验证后墙向和右墙向。视觉、占地、碰撞、顾客座位、
理发师工作位、队列、工具、VFX、方向和 depth 都在同一 Manifest 中；替换视觉资源不需要改服务流程。

在 Unity Play Mode 的命令行参数中加入 `--cut-station-debug`，或在 Web 开发环境使用
`?cutStationDebug=1`，可显示 footprint、collision 和各锚点。该显示只会在 Editor 或 Development Build
响应，正式非开发构建不会出现。工位根对象与 `CutStation` 组件可直接检查当前 orientation、AssetId 和
sorting/depth。

1. 顾客进店后自动进入等待区，并立即显示完整订单气泡。
2. 点击顾客，再点击当前步骤对应的空闲工位：两张 WASH 洗头床均可独立使用，CUT/BLOW 共用理发椅；等候座位保持 FIFO，但服务对象由玩家自由选择。
3. WASH 只显示“花洒、洗发水、毛巾”三个工具：点花洒后长按头部打湿，点洗发水后长按揉洗起泡，再用同一花洒长按冲净，最后单击毛巾快速收尾。
4. 洗完的顾客保持毛巾包头。安排到理发椅后，先快速长按拆毛巾，再进行 CUT 或启动 BLOW。
5. CUT 继续选择剪刀、分齿剪或推子并长按；BLOW 点击启动后后台运行，在合适窗口回来点击结束。
6. 只有完整订单完成才在最后工位旁掉落一份金币；手动拾取后余额才增加。
7. 每天先停在开店准备页，点击“开始营业”后计时和客流才启动。营业倒计时归零后不再进新顾客，但店内服务与金币拾取继续；收尾结束进入只读结算，再进入闭店经营。

更完整、无需懂代码的验收清单见 `Docs/PHASE3_ACCEPTANCE.md`。

## 剪发规则

- `UNDERCUT`：按住时间不足，当前步骤不完成，可再次操作；最终补救成功评为 `RECOVERED`。
- `PERFECT`：完成当前步骤；若气泡还有下一步，则自动激活下一工具；全部一次成功评为 `PERFECT`。
- `OVERCUT`：超过危险阈值立即失败，不等待松手，服务评为 `FAILED`。
- `WRONG_TOOL`：只点击错误工具不处罚；选择错误工具后开始按住顾客才立即失败。

三种工具使用同一个 Long Press 状态机，但参数和反馈不同：剪刀成功区较宽；分齿剪成功区略窄、动作与碎发更细；推子更快、危险阈值更早，并带明显振动和不同音效。

需求气泡使用当前激活工具外圈的 8 段环形进度显示长按状态，不包住整个双需求框，也不显示具体秒数；当前步骤完成后显示勾，并将进度环切换到下一步工具。

## 完成结果、收入与小费

| 结果 | 条件 | 后台结算 |
|---|---|---:|
| `HappyCompletion` | 一次正确完成、服务前未不耐烦、等待与服务均未拖延 | 基础收入 300 + 默认小费 60 |
| `NormalCompletion` | 正确但较慢，或 UNDERCUT 后补救完成 | 基础收入 300 或 120，小费 0 |
| `Failed` | OVERCUT、WRONG_TOOL，或未获服务/长期被冷落后耐心耗尽 | 按原失败规则不结算 |

每个完整订单只生成一份独立 Pickup；订单内的洗、剪、吹步骤不会分步结算。后台严格保存 `OrderIncomeComponent`、`TipIncomeComponent` 与两者之和 `FinalPayment`。余额和 DayStats 只在对应 Pickup 拾取动画完成后增加，快速重复点击不会重复入账；未拾取的钱袋在结算时清理且不作为收入。

右上角显示 1～5 星店铺口碑。口碑按最终顾客结果在 Day 结束时统一变化、跨日保留，并以 0.9～1.1 的轻量倍率影响下一日客流。

## 第六阶段并发规则

- WASH：同一花洒按头发状态自动执行打湿或冲洗；打湿、揉洗、冲洗均为“点工具 + 长按头部”，包毛巾为单击快速动作。首次洗头顾客会收到轻量场景内引导，完成并送往下一工位后写入本机进度，后续顾客不再重复教学。
- BLOW：5～7 秒为最佳结束窗口，7～10 秒轻度超时，超过 10 秒严重超时；所有时间集中配置。
- 拆毛巾默认 0.55 秒；包/拆毛巾不进入订单，不使用独立进度 UI。
- 泡沫完成、待冲洗、待包毛巾的顾客留在原地时会继续占用工位，但玩家可随时将其转移；洗发阶段、后台计时、毛巾和剪发进度均随顾客保留。只有正在长按的主动操作，以及运行中的自动吹发设备会暂时禁止移动。
- 理发工位始终展示拆毛巾、剪刀、分齿剪和推子；系统不自动选择“正确答案”。需求外的洗发或剪发会真实执行、耗时并降低满意度，但不会推进或重新打开订单需求。
- 订单需求全部完成后仍会检查物理阻塞状态；毛巾未拆或洗发液未冲净时不会结算、掉金币或正常离店。
- 同一理发椅上的 `CUT → BLOW` 原地连续进行；跨工位步骤回到待调度状态，不瞬移。
- 正式服务开始后旧排队耐心不再导致顾客突然离店，但等待历史和服务拖延继续影响最终满意度。
- 顾客被安排后，前往工位的移动不会被旧耐心中断；到达后默认有 1.5 秒可配置接管宽限，若始终未开始服务才恢复未服务耐心规则。

## 第七阶段营业日规则

- 默认 Day 配置为 180 秒营业、30 秒固定收尾；它们只是可调默认值，不是硬规则。
- 客流按营业进度经历开店缓冲、正常营业、明显繁忙、最后高峰；中段包含一次约 24 秒的 Rush。
- Director 同时检查场内人数、等候人数、工位占用和生气顾客。过载时只减慢后续客流，不修改耐心、满意度或服务状态；Rush 也不能突破并发硬上限。
- 收尾归零时，未开始服务者记为 `UNSERVED_AT_CLOSE`，已开始但未完成者记为 `INCOMPLETE_AT_CLOSE`，不会追加第二个收尾窗口。
- `DayStats` 从数据层严格拆分订单收入、小费收入、营业奖励、赔偿和其他营业支出；只有完成拾取的钱袋进入订单/小费收入。
- Result 展示订单收入、小费收入、实际营业净收入、完成订单、四类顾客结果及口碑变化，不显示或统计未拾取收入。
- 闭店经营中的投资只扣当前钱包并独立记录，不改写刚刚结束的营业 Result。所有商品始终可见，锁定项展示解锁条件。
- 暂停按钮统一冻结营业/收尾倒计时、刷客、耐心、泡沫、手动/自动吹发及服务计时。

## 当前实现边界

- 固定地图、镜头、HUD、工位位置及界面风格不变。
- 一个逻辑洗头工位和两个理发工位可独立服务；等待区仍自动入座和补位，具体服务工位由玩家选择。
- 世界时间与其他顾客的后台任务在剪发聚焦和长按期间持续推进；当前顾客进入有效服务后暂停等待耐心，切走后先进入可配置宽限期，再恢复被冷落计时。
- 点击或切换顾客不会回满耐心；只有首次有效操作给予有限情绪缓解。原子长按期间不触发离店，阈值事件延迟到操作结束后的安全节点处理，既往等待记录仍会阻止升级为 Happy。
- 染发、烫发、毛巾库存、洗衣机、员工、升级、剧情、自由剪发、毛发物理和发型编辑器不属于本阶段。
- 角色、家具、三种工具、碎发和金币均为可替换的灰盒占位资源。
