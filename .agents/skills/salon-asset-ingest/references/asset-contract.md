# Asset intake contract

## Authoritative paths

- Inbox: `assets/inbox/`
- Archive: `assets/archive/`
- Generated previews: `assets/previews/`
- Imported runtime images: `unity-hair-salon/Assets/Resources/Imported/`
- Manifest: `unity-hair-salon/Assets/Resources/AssetPipeline/asset-manifest.json`
- Asset lab evidence: `unity-hair-salon/Builds/PipelineEvidence/`

## Required Manifest fields

Every entry requires a stable ID, supported type, Resources path, status, supported directions, normalized pivot, positive footprint and collision areas, shadow config, interaction anchors/required anchor IDs, and sorting information.

Allowed values:

- status: `draft`, `review`, `approved`, `deprecated`
- directions: `back-wall`, `right-wall`, `free`
- IDs and normalized files: lowercase kebab-case

Furniture contact shadows are generated by `ContactShadow`; do not bake a permanent floor shadow into a new furniture image. Configure size, offset, opacity and softness in the Manifest.

## Image inspection decisions

- The file must decode as PNG/JPG/WEBP; ordinary product intake should use PNG.
- Completely transparent or under 2% visible-bounds images are errors.
- Report alpha absence. Treat it as an error for characters/furniture explicitly approved as transparent cutouts; it may be valid for opaque panels only when confirmed.
- Large one-sided transparent margins are warnings requiring pivot review, not an invitation to crop by eye.
- Visible pixels touching the image boundary are a potential truncation warning. Compare with the approved source before changing it.

## Safe rollback

The intake tool protects `approved` IDs and archives the submitted source. If a draft intake must be reverted, remove only the exact new ID’s Manifest entry, `Resources/Imported/<id>.*`, `assets/previews/<id>.png`, and its archived inbox source. Re-run Node tests and `BuildScript.ValidatePipeline`. Use version control when available; never restore by replacing another approved file.
