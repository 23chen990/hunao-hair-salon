# 项目自动接棒协议

> 目的：防止“子任务已经完成，但主任务没有继续”的空转状态。

## 单一事实来源

- 长期策略：`PROJECT_PLAN.md`
- 当前进度：`PROJECT_STATUS.md`
- 机器可读运行态：`PROJECT_RUN_STATE.json`
- 产品决策：`docs/decisions/`

任何可见子任务的聊天状态都不是项目总状态。子任务显示“完成”，只表示它的局部交付结束，必须由主任务回收。

## 不允许出现的状态

满足以下三项即视为流程错误：

1. 没有运行中的核心实现任务；
2. `PROJECT_RUN_STATE.json` 的队列仍有安全本地工作；
3. 没有明确记录用户阻塞项。

心跳发现该状态时，必须立即启动队首任务，不能只汇报“目前空闲”。

## 子任务完成后的强制回收

每个子任务结束后，主任务必须依次完成：

1. 读取子任务最终报告。
2. 在文件系统确认交付物真实存在。
3. 独立复跑与风险成比例的测试、构建或媒体检查。
4. 将任务从 `activeTasks` 移到 `completedTasks`。
5. 更新 `PROJECT_STATUS.md` 和 `PROJECT_RUN_STATE.json`。
6. 若队列仍有安全本地工作，立即启动下一任务并记录 thread id。
7. 只有遇到用户门槛或产品方向决策，才允许进入 `waiting_for_user`。

## 心跳

Codex 当前任务已启用“小游戏项目自动接棒”心跳。它定期检查运行态与可见子任务，负责完成上述回收流程。

心跳不是重复开任务的借口：

- 任意时刻最多一个核心实现任务。
- 可额外并行一个互不写同一目录的素材/研究任务。
- 启动前先检查任务标题、thread id、目录所有权和现有文件，防止重复。
- 任务失败时先读取原因；相同安全方案最多重试一次，之后记录真实阻塞。
- 必须区分“产品/实现门槛失败”和“宿主环境未能执行”：沙箱权限、浏览器启动、端口或缺失宿主能力只能记为 `ENVIRONMENT_UNVERIFIED`，不得直接写成玩法 `KILL`。主任务回收时应按正常权限流程独立复验一次；只有真实验收断言失败，才进入产品淘汰判断。

## 唯一允许自动暂停的条件

- 身份证、人脸、手机号、银行卡或账号实名认证。
- 登录、注册、签署协议、提交平台审核。
- 对外发布、发送消息、广告投放、采购或付款。
- 缺少真人外部数据，继续开发会改变已锁定的产品决策。
- 需要用户在两个会实质改变产品方向的方案中做选择。

暂停时必须：

1. 在 `PROJECT_RUN_STATE.json` 写入一个具体 `userGate`，不能写“等待反馈”这种空话。
2. 告知用户已经完成什么、只需要他做哪一个动作。
3. 将心跳暂停，避免重复提醒或偷偷扩大范围。
