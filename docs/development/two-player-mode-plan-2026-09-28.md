# 《胡闹理发店》本地双人模式方案

日期：2026-09-28

## 目标

在现有 Unity Demo 中增加可选的同设备本地双人模式。默认入口和单人玩法保持不变；使用 `?multiplayer=1`（或开发命令行 `-salonMultiplayer`）进入双人模式。

## 玩法范围

- 两位理发师在同一个理发店里协作。
- 客流、营业倒计时、顾客订单、满意度、收入、扩建和存档仍属于一个共享店铺。
- 每位玩家独立拥有角色位置、输入、当前目标顾客、服务计时和 `PlayerContext`。
- 两位玩家可以同时服务不同顾客；同一顾客的主动操作只能被一位玩家占用，完成或取消后释放。
- 双人模式复用已有接待、安排工位、洗发、冲洗、吹发和剪发流程，不新增服务、货币、升级页面或事故规则。

## 输入与画面

| 玩家 | 键盘移动 | 键盘操作 | 触控 |
| --- | --- | --- | --- |
| P1 | WASD | Space | 左半屏摇杆 + 操作键 |
| P2 | 方向键 | Right Ctrl / Keypad Enter | 右半屏摇杆 + 操作键 |

- 保持一个共享横屏镜头，镜头跟随两位玩家的平面包围盒中心，避免一人离开画面。
- 正式 HUD、队列、营业目标和结算仍只有一套；两套控制面板只在双人模式出现。
- P2 使用独立颜色提示和操作文字，角色脚下增加轻量识别标记。

## 技术拆分

1. **输入层**：扩展 `SalonMobileControls`，保留现有 `Create(Transform)` API，增加玩家编号和左右半屏布局；键位映射保持纯函数可测试。
2. **运行时层**：新增 `SalonCoopPlayerState` 保存 P2 的角色、控制、目标和主动服务状态；P1 继续使用现有单人字段，降低单人回归风险。
3. **模型网关**：为洗发、冲洗、剪发开始/完成增加带 `playerId` 的重载；旧 API 保留原有单人互斥语义。顾客增加主动操作所有者字段，防止两位玩家同时修改同一顾客。
4. **场景集成**：仅由主集成任务修改 `SalonDemo` 的启动、更新、角色生成、控制面板和共享镜头；资产测试场景不接入双人调试 UI。
5. **证据**：开发构建在 `?multiplayer=1&multiplayerEvidence=1` 下输出 `[MULTIPLAYER_READY]` 和 `[MULTIPLAYER_FLOW_PASS]`，正式发布 UI 不显示调试文字。

## 测试与验收

- 先新增失败的 EditMode 测试：键位隔离、两个 `PlayerContext` 独立、不同顾客并行操作、同一顾客互斥及释放、结算只产生一笔收入。
- 通过后运行 Unity 全量 EditMode，检查 XML `result=Passed` 且 `failed=0`。
- 运行 Node 资产管线测试和 UI 字体检查。
- 构建 WebGL Demo，在 844×390 Chromium 视口打开 `?multiplayer=1`，确认双角色、双控制面板、两个输入映射、共享计时/结算和零 console/request 错误。
- 最后运行项目既有全量门禁，确保默认单人路径不回归。

## 当前明确限制

- 这是本地同屏协作，不包含联网同步、房间、账号、平台 SDK 或断线重连。
- 双人模式沿用一个店铺存档和一个共享经济；不会为双人另建存档槽。
- P2 不拥有独立的经营 HUD，服务进度通过顾客世界反馈和自己的控制提示显示。
