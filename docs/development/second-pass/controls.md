# 第二轮触控组件布局契约

日期：2026-09-28

## 复现

上一轮双人窄横屏证据 `Builds/FirstSessionVisual/final/phone-narrow-640x360-two-player-business-two-players-separated.png` 中，P1/P2 操作按钮已经分别位于左右半屏；实际问题是按钮向上覆盖等候顾客气泡和座椅阅读区，底部营业画面被压缩。`Builds/FirstSessionVisual/final/844x390-two-player-business-static.png` 同样显示底部操作面偏高，挤压营业区。

## 可测契约

`SalonMobileControls` 的 UI 参考空间是 1920×1080。640×360 时缩放比例为 1/3，因此每个移动和操作命中面在宽、高两个方向都至少保留 132 个参考单位（44 个物理像素）。按钮文字在该视口至少保留 14 个物理像素，提示文字在显示时至少保留 9 个物理像素。

分屏时，P1 的 joystick、操作按钮和提示必须完整位于参考空间左半 `[0, 960]`，P2 的对应控件必须完整位于右半 `[960, 1920]`。操作按钮的顶部不得高于参考坐标 240（640×360 时距离底部 80px），给等候区和顾客气泡留出可见空间。同一玩家的移动面、操作面和提示不得相互覆盖；两名玩家的同类命中面也不得重叠。测试会从固定 1920×1080 Canvas 的世界角点还原实际矩形，避免把父级半屏锚点或右锚偏移误算成全屏坐标，也避免只检查透明度或只断言字号。

测试文件：`unity-hair-salon/Assets/Tests/SecondPassControlsTests.cs`。主代理应先运行该过滤器确认当前实现红，再在 `SalonMobileControls.cs` 中做最小分屏布局调整，随后复跑同一过滤器和全量 EditMode 测试。Unity、WebGL 和 Chromium 验收由主代理串行完成。

本轮实现保持原有 joystick、提示条的位置、宽度和字号、右下锚点及按钮宽度，只在 `splitScreen` 下将操作按钮高度从 200 缩为 132 个参考单位，并将提示条高度从 76 缩为 72 个参考单位。半区宽度为 960 时，P1 操作矩形为 `(500,104)-(860,236)`，P2 为 `(1460,104)-(1820,236)`；两者中心分别落在参考坐标 `(680,170)` 和 `(1640,170)`，640×360 时约为 `(227,57)` 和 `(547,57)` 物理像素。提示条保持底部 `y=18`，上缘为 `90`，与原 joystick 底缘 `y=92` 留 2 ref 间隔。按钮仍保持 360 ref 宽和 48 ref 字号，单人布局不变。

## 验证状态

`Builds/SecondPassControlsSatisfactionRed.xml` 记录了实现前操作按钮顶部 `304 > 240.01` 的有效失败；修复后的 `Builds/SecondPassFinalEditMode.xml` 为 731/731 通过。主代理继续负责最终 Unity、WebGL 与真实 Chromium 截图验收。

## 验收关注点

- 640×360 双人画面中，P1/P2 控件分别留在自己的半屏，不压到对方命中面。
- 缩小后的控件仍可触达，操作按钮中文字完整可读。
- 提示面如果显示，不能重新覆盖移动或操作命中面。
- 保持现有单人控件、页面结构、视觉颜色和按钮语义，不新增页面、按钮或教程。
