# 开局单双人和存档槽方案（2026-09-28）

## 背景与参考

《胡闹厨房 2》的本地流程先让玩家加入，再由主玩家进入故事、街机或对战等模式；官方 FAQ 同时明确提供 3 个存档槽（[Team17 FAQ](https://www.team17.com/news/overcooked-2-faq)）。Team17 的共享进度说明也强调，参与者围绕战役进度保存（[Shared Progress update](https://www.team17.com/news/overcooked-2-shared-progress-update-available-now)）。这个项目已经有本地双人输入和共享经营模型，因此只补充开局选择，不改变营业规则、家具布局或经济系统。

## 玩家流程

1. 正常进入横屏 Demo 后显示「选择游戏模式」卡片。
2. 点击「单人」或「双人」；双人会启用现有 P1/P2 键位与左右触控区。
3. 进入「选择存档」卡片，展示 3 个槽位：空槽显示「新存档」，已有槽显示当前天数、金币和已完成天数。
4. 点击槽位后显示「开始这份存档」，确认后关闭开局选择卡，进入现有「DAY N / 开店准备」卡片。
5. 原有开始营业、经营、闭店和自动保存流程保持不变。单双人是当前会话设置；存档槽只保存现有 `SalonProgressData`。

## 数据与兼容

- 保留原有 `PrimaryKey` / `BackupKey` 作为 1 号槽，旧玩家进度自动出现在 1 号槽。
- 2、3 号槽使用同一份校验、备份和原子保存逻辑，不改变 `SalonProgressData` 的 JSON 结构。
- 选择双人不会把玩家身份写进存档；同一槽可在下一次以单人或双人继续。
- 测试、编辑器验收和 BrowserCoreFlowSmoke 继续绕过开局卡，保持既有自动化入口稳定。

## 实现边界

- 复用现有 `BuildModalSurface`、`UiPanel`、`UiLabel`、`UiButton` 和已批准的色板，不新增图片或正式场景资产。
- 启动选择卡是正常移动端入口的一部分，只在 `_mobileMode` 且没有自动化验收参数时显示。
- 切换槽位只允许发生在 `PreOpen`，清理当前尚未开始的日状态后按现有恢复路径加载新槽，刷新设备扩建、资金、声誉和日期。
- 不添加删除槽位、账号、联网、货币或额外玩法；空槽首次确认即写入默认进度。

## 验收

- EditMode：模式解析、三槽 key 隔离、旧 1 号槽兼容、槽位摘要与空槽行为。
- Node 资产管线、Manifest/资源检查、Unity 全量 EditMode、WebGL 构建。
- 真实 Chromium：正常入口可完成「单人/双人 → 槽位 → 开店准备」，双人槽进入后 P1/P2 均可移动；刷新后所选槽的天数/金币仍可见。
