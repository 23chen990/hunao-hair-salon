# 单人手游 Demo · 2026-09-16

## 这一轮的体验

横屏进入后，左摇杆移动理发师，右侧按钮会根据附近的顾客或工位变成接待、安排、洗发、剪发、启动吹发或收尾。服务必须走到现场；远处点击顾客、工位不会直接开始工作。桌椅和墙边有碰撞限制。

先完成一个短订单，随后洗剪吹组合和排队压力逐步增加。洗发、剪发需要理发师短暂留在现场；启动吹发后可以去接待和服务另一位顾客，再返回收尾。订单只要求洗剪时，完成洗剪即可结账。等候卡片显示需求、编号、耐心；工位提示后台运行或待收尾。

每次营业 3 分钟，另有最多 15 秒收尾。3 分钟参考《胡闹厨房》常见的可操作关卡范围；收尾是独立的离场/结算缓冲。第 1、2、3 天的目标分别暂定为 3、4、5 单，第 3 天以后维持 5 单。第一天就会出现排队和后台吹发；这些是待真人试玩调整的入门数值，自动操作成绩不能代表真人难度。达标后进入现有设备经营页面，未达标可免费重试。自动吹发基础功能从第一天可用，现有支架购买用于改善效率与容错。

这次继续检查还发现：一键洗发后的组合订单可能被旧毛巾步骤卡住；原吹发窗口也不足以支持一次完整的跨工位服务。两项均增加了专门回归：订单按实际的一键洗发完成记录推进，手游吹发留出接待另一位顾客、完成短服务再返回的时间。

钱包、设备、天数、口碑、满意度和已通过的目标会保留。刷新已经结算的一天会回到闭店经营；中途退出则从当天开店前重新开始，避免半笔收款或半次服务被保存。重试也恢复开店前状态。切到后台或暂停时，角色停止移动、营业计时暂停。

## 体验方法

1. 电脑本地入口：<http://127.0.0.1:8912/WebGLDemo/>。也支持 WASD / 方向键移动和空格操作。
2. 手机与这台电脑连接同一局域网，横屏打开：<http://172.16.133.209:8912/WebGLDemo/>。电脑需保持运行；IP 改变时需要使用新的局域网地址。
3. 资产实验室：<http://127.0.0.1:8912/WebGLAssetLab/>。
4. 若预览服务已结束，在仓库目录运行 `python3 tools/serve-salon.py --bind 0.0.0.0 --port 8912`。

建议先完成第一位剪发顾客，再安排一位洗发顾客；吹发开始后立刻接待下一位。关注左侧耐心条及工位的待收尾提示。

## 忙乱感与 IAA 的判断

当前忙乱来自跑动距离、有限工位、顾客耐心和后台吹发收尾的冲突。重点体验是“先开 A 的吹发，趁空处理 B，再回来收 A”，而不仅是不断加快来客。已确认满意度没有按同一顾客重复结算；达标后仍需照顾店内顾客，等到打烊未完成会扣分。扣分幅度是否过重保留给真人测试，不把脚本绕路造成的流失当作玩家表现。

成熟竞品的核实记录和具体建议见 [IAA 设计笔记](iaa-design-notes-2026-09-16.md)。建议先保留无广告基线，之后优先测试结算处的自愿奖励，免费重试一直保留；营业中不打断。当前只有有限订单与一个设备购买项，还没有证据支撑长期留存或广告收入。

## 当前范围

本次交付是可触屏试玩的 WebGL 手游 Demo。Android / iOS 安装包、真机性能与不同刘海安全区仍需在目标设备上验收。正式广告平台未确定，本轮没有接入广告 SDK，也没有放置假的广告奖励按钮。数值节奏已形成可调配置，是否足够有趣还需要真人试玩反馈。
